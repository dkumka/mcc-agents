# Архитектура mcc agents

```
браузер (телефон / Mac)
   │ https://agents.mcc.example.com  (nginx, basic auth code.htpasswd)
   ├── /            → 127.0.0.1:3110  mcc-agents-web   (Next.js: только интерфейс, без состояния)
   └── /api/*, /ws  → unix:/run/mcc-agents/agentd.sock  mcc-agentd
                                   │
                                   ├── claude -p --input-format stream-json … (процесс на активный чат)
                                   ├── codex app-server (один на все треды, JSON-RPC по stdio)
                                   └── agy acp (Antigravity, один на все сессии, ACP — JSON-RPC 2.0 по stdio)
```

Почему демон отдельно от Next: процессы агентов должны жить, пока идёт работа (фоновая задача Claude живёт внутри
процесса `claude` и пропадает с ним). Next можно пересобирать и перезапускать сколько угодно — чаты не прерываются.

## agentd (`apps/agentd/src`)

| Файл | Что делает |
|---|---|
| `index.ts` | запуск: store, hub, адаптеры, сервер, периодический `refresh` (10 с) и `sweep` (60 с) |
| `config.ts` | пути, сокеты, таймауты (переменные `AGENTD_*`) |
| `server.ts` | HTTP API + WebSocket (`ws`). Два сокета: `agentd.sock` (nginx, 660 codeweb) и `local.sock` (600, для `ssh -L`; ещё и проксирует всё прочее в Next). Проверка Origin = Host для WS |
| `hub.ts` | список всех чатов (обоих агентов), подписки браузеров, создание чатов, уведомления, `projects()` |
| `chat.ts` | состояние одного чата: нормализованные элементы + live-состояние; рассылка изменений, батчинг дельт (40 мс), усечение больших выводов на проводе |
| `store.ts` | `~/.local/share/mcc-agents/state.json`: закрепления, свои названия, настройки чатов, lastSeen, лимиты, окна контекста моделей |
| `tools.ts` | классификация инструментов Claude (Bash/Edit/Read/…) → категория, заголовок, diff |
| `fsapi.ts` | файлы, дерево, поиск файлов для `@` (`rg --files`), `git status/diff` |
| `claude/sessions.ts` | инкрементальный скан `~/.claude/projects/*/*.jsonl` (чтение с последнего смещения), загрузка истории |
| `claude/normalize.ts` | строки транскрипта / события stream-json → `ChatItem` (общий код для истории и live) |
| `claude/index.ts` | `ClaudeProc` (процесс на чат) и `ClaudeAdapter` |
| `codex/rpc.ts` | клиент `codex app-server` (JSON-RPC, автоперезапуск) |
| `codex/index.ts` | `CodexAdapter`: треды, история (`thread/turns/list`, itemsView full), события, подтверждения |
| `antigravity/acp.ts` | клиент `agy acp` (Agent Client Protocol: JSON-RPC 2.0, NDJSON по stdio; запуск по первому запросу, автоперезапуск после падения) |
| `antigravity/index.ts` | `AntigravityAdapter`: сессии, история (replay `session/load`), события `session/update`, подтверждения и вопросы `ask_question` |
| `antigravity/questions.ts` | разбор `ask_question` (`(Recommended)`, мультивыбор), заголовок карточки и форматирование ответов для `session/prompt` |

### Claude

- Запуск: `CLAUDE_CODE_ENTRYPOINT=mcc-agents claude -p --input-format stream-json --output-format stream-json --verbose
  --include-partial-messages --permission-prompt-tool stdio --allow-dangerously-skip-permissions (--session-id|--resume) <id>
  [--model] [--effort] [--permission-mode]`.
  - `CLAUDE_CODE_ENTRYPOINT=mcc-agents` — иначе `-p` помечает сессию `sdk-cli`, и терминальный `claude --resume` её скрывает.
  - `--permission-prompt-tool stdio` — запросы разрешений приходят как `control_request can_use_tool`; ответ `allow`
    (+`updatedInput`, +`updatedPermissions` из `permission_suggestions`) / `deny`. Так же идут `AskUserQuestion`
    (ответы в `updatedInput.answers`) и `ExitPlanMode`.
- Control-запросы демона: `initialize`, `interrupt`, `set_model`, `set_permission_mode`, `apply_flag_settings {effortLevel}`,
  `get_context_usage` (после каждого хода — точный % контекста), `stop_task`.
- События: `stream_event` (дельты текста/мыслей), `assistant`/`user` (блоки, результаты инструментов, `tool_use_result`
  со `structuredPatch` для diff), `system` (`init`, `status`, `task_*`, `compact_boundary`, `api_retry`, `session_title_changed`,
  `thinking_tokens`), `result`, `rate_limit_event` (окна `five_hour`, `seven_day…`).
- Очередь и дополнения: сообщение во время работы пишется в stdin. CLI обычно **подмешивает его в текущий ход**
  (`queued_command`, в истории — `queue-operation remove`), реже выполняет следующим ходом — поэтому `result` не по одному на
  сообщение. Учёт — по `command_lifecycle` (`queued` → `started` → `completed`, по `uuid` нашего сообщения): чат свободен,
  когда пришёл `result` и все отправленные сообщения `completed` (последнее `completed` приходит после `result`). Без этих
  событий (старый CLI) — счётчик результатов. «Стоп», после которого CLI 4 с ничего не присылает (кроме ответа на сам
  interrupt), переводит чат в «свободен» (`settleIfQuiet`). До 2026-11-18 дополнение посреди хода оставляло чат в
  «Работает» навсегда.
- Простаивающий процесс (`AGENTD_CLAUDE_IDLE_MS`, 20 мин) закрывается, если нет хода, подтверждений и фоновых задач;
  следующее сообщение поднимает его через `--resume`.
- Перед `--resume` проверяется `/proc`: если сессию держит другой `claude` (терминал), чат не запускается и показывается
  баннер — две программы в одной сессии испортили бы историю.
- Возможности (модели, слэш-команды, skills, режим по умолчанию, тариф) — короткий `claude -p` только с `initialize`
  (без запроса к API), кэш 10 мин на папку.

### Codex

- Один `codex app-server`; при открытии чата — `thread/resume` (подписка на события) + `thread/turns/list`.
  Новый чат — `thread/start {cwd, model, approvalPolicy, sandbox}`, сообщение — `turn/start`
  (модель, effort, approvalPolicy и sandboxPolicy на каждый ход), во время хода — `turn/steer`.
- Подтверждения: серверные запросы `item/commandExecution/requestApproval`, `item/fileChange/requestApproval`,
  `item/tool/requestUserInput`, `item/permissions/requestApproval`. Профили панели: `read-only` (sandbox read-only + never), `on-request` (workspace-write + on-request),
  `never` (danger-full-access + never). Настройки сохраняются в метаданных чата и применяются при start/resume/каждом turn.
  Старые чаты без профиля получают workspace-write + on-request. Неизвестный профиль отклоняется.
  Во время активного хода Codex смена профиля отклоняется: сначала остановить ход.
  Полный доступ ограничен правами Linux/systemd, не предоставляет sudo. В Claude добавлен bypassPermissions;
  процесс запускается с --allow-dangerously-skip-permissions, переключение идёт через set_permission_mode.
- События: `item/started|completed`, дельты (`agentMessage`, `reasoning`, `commandExecution/outputDelta`),
  `turn/plan/updated` (→ список задач), `thread/tokenUsage/updated` (контекст), `account/rateLimits/updated` (лимиты).
- `clientUserMessageId` = наш id сообщения → своё сообщение не дублируется.
- `/compact` → `thread/compact/start`. Картинки → `uploads/<uuid>.<ext>` → `localImage`.

### Antigravity (`agy`, с 2026-11-23)

- Официальный штатный режим для внешних клиентов — **`agy acp`**: сервер Agent Client Protocol, через который к агенту
  подключаются Zed и JetBrains. `clientInfo.name` = `mcc_agents`; клиент не даёт агенту ни `fs/*`, ни `terminal/*` —
  файлы и команды агент делает сам, как в терминале. Вход — собственный Google-вход CLI (`agy` в терминале), токены оболочка
  не читает. Бинарник — `~/.local/bin/agy` (`AGY_BIN`), обновляется сам.
- Один процесс на все сессии. `session/list` — список (cwd, название, `updatedAt`; признака «из веба» нет — его даёт
  `state.json`). `session/load` — открыть: история приходит повтором `session/update` до ответа (элементы кладутся молча),
  ответ — модели, режимы, `configOptions`, тариф (`_meta.antigravity.tier`, «Google AI Pro» → внизу левой панели).
  `session/new {cwd}` — новый чат. Системного промпта в ACP нет, но agy берёт дополнение к нему из
  `_meta.antigravity.systemPrompt.append` в `session/new` и `session/load` (проверено 2026-11-26 пробными сессиями; варианты
  `_meta.systemPrompt`, `_meta.systemPrompt.append`, `_meta.antigravity.systemPrompt` строкой agy молча игнорирует). Ещё agy
  читает `AGENTS.md`/`GEMINI.md`/`.agents/rules/*.md` от папки сессии вверх до корня репозитория и `~/.gemini/config/`, но
  писать туда за пользователя не нужно. Артефакты разговора agy кладёт в `~/.gemini/antigravity-cli/brain/<id>/`; у `agy acp`
  есть `--gemini-dir` / `--app-data-dir`, но там же вход и история, которые общие с терминалом, поэтому путь не меняем, а
  читаем `brain/` (см. «Отдача файлов»). Повтор истории может продолжаться и **после** ответа на `session/load` (видели: последний
  ответ пришёл через ~0,3 с) — адаптер считает его повтором, пока сессия не помолчит 0,6 с (не дольше 5 с); иначе конец
  истории становился «живым» ответом с вечной кареткой «пишет…» и поднимал чат непрочитанным.
  Простаивающие сессии **не закрываются** (`sweep` отпускает только треды Codex): `session/close` у agy гасит фоновые задачи
  сессии (`kill_background_tasks=true` в его журнале).
- Ход — `session/prompt` (без таймаута). **Дополнение посреди хода** — ещё один `session/prompt`: agy подмешивает его в текущий
  ход, а предыдущий запрос сразу возвращается с `end_turn`. Поэтому ход кончается, когда вернулся *последний* запрос
  (счётчик `inflight`). Проверено: «…ответь FIRST» + посреди хода «добавь SECOND» → один ответ «FIRST SECOND».
- «Стоп» — уведомление `session/cancel`; висящие запросы разрешений получают ответ `cancelled` (так требует ACP); запрос
  возвращается с `stopReason: cancelled` → «Прервано». Если агент 8 с молчит — чат всё равно освобождается.
- События `session/update`: `agent_message_chunk` / `agent_thought_chunk` (подряд идущие куски — один элемент),
  `tool_call` + `tool_call_update` (сливаются по `toolCallId`; `kind` → категория карточки; `content.diff` → diff,
  у `execute` из вывода убирается шапка «Created At … Command output:»), `plan` → список задач, `usage_update` → контекст,
  `session_info_update` → название, `available_commands_update` → слэш-команды, `current_mode_update`, `config_option_update`.
- Долгие команды agy сам уводит в фон и заканчивает ход — карточка остаётся «выполняется», пока не придёт её завершение.
  Когда фоновая задача кончается, agy может сам продолжить разговор между ходами: такие события показываются, чат поднимается
  в списке и становится непрочитанным, статус не меняется (конца такого «хода» ACP не сообщает); текст такого ответа
  закрывается (без каретки) после 3 с тишины.
- Подтверждения: запрос агента `session/request_permission {toolCall, options}`. `execute` → карточка команды, `edit` →
  правка с diff. Ответ — `optionId` нужного `kind` (`allow_once` / `allow_always` / `reject_once`). Комментарий к «Отклонить»
  уходит агенту следующим `session/prompt` (дополнение в тот же ход).
- **Вопросы `ask_question`** (`antigravity/questions.ts`, `web/src/lib/questions.ts`): отдельного ACP RPC-запроса под вопросы
  в `agy acp` нет — агент присылает `tool_call` `ask_question` (`rawInput.questions`: `question`, `options`,
  `is_multi_select`), сразу дублирует вопросы текстом (`- [1] (Recommended) …`) и завершает ход (`end_turn`), оставляя
  инструмент открытым. Адаптер классифицирует `ask_question` как `question`, поднимает штатный `Approval` (`kind: 'question'`)
  и сохраняет его (вместе со статусом `waiting` и Telegram-уведомлением) поверх `end_turn` до ответа, пропуска, отмены или
  обычного сообщения пользователя; при ответе собирает структурированный текст с индексами `[N]` и отправляет его через
  `session/prompt`. При `session/load` незавершённый `ask_question` в хвосте истории восстанавливает форму (без статуса
  `waiting`, чтобы старые чаты не держали `busy`), а уже отвеченные закрываются как `done`. В вебе дубль-текст от `agy acp`
  сворачивается в раскрываемую карточку `ask_question` (`isAskQuestionEcho`), а форма `QuestionForm` (`approval-panel.tsx`)
  для всех трёх агентов работает пошаговым степпером при нескольких вопросах, выносит `(Recommended)` в бейдж «Рекомендуется»
  и предлагает кнопку «Рекомендуемые».
- Модели: `availableModels` вида `gemini-4-neon-high` → модель `gemini-4-neon` + глубина `high` (у Orchestrator глубины нет,
  у GPT-OSS — только `medium`); выбор — `session/set_model` с полным id. До первой сессии в процессе список берётся из
  `agy models`. Режимы — `session/set_mode`: `default` «Спрашивать», `accept-edits` «Правки без вопросов», `plan` «План».
- **Режим Auto** agy даёт только при своей песочнице для команд (user + mount namespaces), а Ubuntu запрещает их обычным
  программам (`kernel.apparmor_restrict_unprivileged_userns = 1`; в журнале agy было «auto mode is unavailable because the
  terminal sandbox is unavailable»). С 2026-11-23 — точечный профиль `/etc/apparmor.d/agy` (как у chrome/code в Ubuntu:
  `flags=(unconfined)` + `userns`, только для `~/.local/bin/agy`; поставил пользователь). Проверено: режим `auto` в
  ответе сессии, команда в Auto выполняется без вопроса в своих user/mnt namespaces. Дочерние процессы agy наследуют профиль
  (`/proc/self/attr/current` = `agy (unconfined)`). Профиль цепляется при запуске — после установки/снятия перезапустить
  `agy acp` (`kill` его процесса: адаптер поднимет заново).
- Режим по умолчанию: новый чат и чат без режима в `state.json` — `auto`, если agy его даёт, иначе «Правки без вопросов».
  До первой сессии в процессе режимы неизвестны — `sandboxLikely()` (снят запрет в ядре или у процесса `agy acp` своя метка
  AppArmor); после первой сессии — её список. Без профиля (`sudo apparmor_parser -R /etc/apparmor.d/agy && sudo rm …`)
  всё возвращается к «Правки без вопросов».
- Нет в ACP, поэтому нет в вебе: форков и откатов (кнопки скрыты, `canBranch` в `lib/format.ts`), остановки фоновых задач.
- **Лимиты** (с 2026-11-23) — не из ACP, а из `agy -p "/usage" --output-format json`: штатный неинтерактивный ответ CLI на
  `/usage` (без хода агента, квота не тратится, ~3 с). Опрос: после каждого хода (и с ошибкой — она может быть о лимите), при
  старте демона и при подключении браузера — если данных нет или им больше часа. По таймеру — никогда; один запуск за раз.
  Лимиты agy — по группам моделей (Gemini / Claude и GPT / Argon), у каждой своё окно 5 часов и неделя: `LimitWindow` с
  `groupId`, `group`, `models` (базовые id моделей группы — по списку из описания группы). Под полем ввода — группа модели
  чата, внизу панели — первая (Gemini), в карточке — все группы. Если запрос лимитов завершился ошибкой (например,
  `Eligibility check failed`), адаптер сохраняет текст ошибки в `AgentLimits.error` и `errorAt` (при успешном ответе поля
  очищаются), а веб (`LimitsInline`) показывает «лимиты недоступны» и причину в карточке по нажатию/наведению вместо
  «лимиты появятся после первого запроса». В терминале тот же разговор — `agy --conversation <id>`.
- Тестовый экземпляр демона рядом с рабочим: `AGENTD_SOCKET=/tmp/… AGENTD_LOCAL_SOCKET=/tmp/… AGENTD_DATA=/tmp/…
  AGENTD_NOTIFY=0 AGENTD_TELEGRAM=0` (без последнего два демона дерутся за опрос Telegram-бота) и PATH с `~/.npm-global/bin`
  (иначе не найдётся `codex`); сквозной тест — `scripts/e2e.mjs <сокет> antigravity <папка>`.

## Режимы «Чат» и «Код»

- Переключатель вверху левой панели (`app-sidebar.tsx → ModeSwitch`). «Код» — работа в проектах (список по папкам, выбор
  проекта). «Чат» — беседы вне проектов: список по датам («Сегодня», «Вчера», «Последние 7/30 дней», месяцы), экран новой
  беседы с приветствием, в шапке «Беседа · модель», без вкладки «Изменения».
- Режим чата определяется по папке: всё, что лежит в `~/chat/` (`config.chatRoot`, `AGENTD_CHAT_ROOT`), — беседа
  (`chat-dirs.ts → isChatDir`, `ChatSummary.mode`). Протокол и старые чаты менять не пришлось; в «Проекты» эти папки не
  попадают.
- **Папка на каждую беседу:** `create` с `mode: 'chat'` → сервер сам делает `~/chat/<дата>-<6 hex>` (`newChatDir`). Файлы
  беседы лежат отдельно; удалить беседу с файлами — удалить папку. Вложения — по-прежнему в общей папке загрузок.
- **Инструкции беседы:** `~/chat/AGENTS.md` (текст в `chat-dirs.ts`, обновляется при старте демона, пока в файле есть
  строка-метка; убрать метку — править вручную) и `~/chat/CLAUDE.md` = `@AGENTS.md`. Claude читает его из родительской
  папки, Codex — по ссылке `AGENTS.md → ../AGENTS.md` в каждой папке беседы (Codex смотрит только в свою папку; ссылка
  скрыта в панели «Файлы»).
- **Правила сервера (`DEV-ENVIRONMENT.md`) в беседах:** у Claude их нет — на сервере они подключены через `~/dev/CLAUDE.md`,
  а не глобально (см. журнал `mcc-server`, 2026-11-12). У Codex глобальный `~/.codex/AGENTS.md` отключить нельзя — в
  инструкциях беседы сказано не ориентироваться на них.
- **Настройки новой беседы** не запоминаются: каждый раз Claude Opus (Codex — в одно нажатие), уровень рассуждения по
  умолчанию, права «Авто» (Claude — `auto`, Codex — `on-request`, «Модель решает»). Режим и последний открытый чат каждого
  режима помнит браузер (`localStorage.mode`, `store.switchMode`); адрес — `?mode=chat`, `?new=1&mode=chat&agent=codex`.
- В Telegram-подтверждениях беседы помечены «💭 беседа» вместо папки проекта.
- **Ход работы свёрнут** (только веб, `message-list.tsx → foldTurns / WorkGroup`). В каждом ходе (всё после сообщения
  пользователя) сворачивается всё до последнего шага (`tool` / `thinking`), включая промежуточные реплики агента. На виду
  остаётся то, что после него, то есть ответ. Предупреждения и ошибки (`notice` не `info`) выносятся из свёртки.
  В строке: длительность (по `ts` первого и последнего шага), счёт шагов по категориям (`todo` и `ToolSearch` не считаются)
  и ошибки. У идущего хода — текущее действие и время, отдельная строка «Работает» тогда не нужна. Подтверждения — в
  `ApprovalPanel`, они не в ленте. Вид задаёт `ui.work[mode]` (`localStorage.showWork`): беседы по умолчанию свёрнуты, код
  развёрнут. Переключатель — в меню чата.
- **Инструкции беседы** говорят агенту, что пользователь видит только итоговый ответ (без «сейчас посмотрю…»), что git
  здесь нет и что файлы создаются только по делу.
- **«Перенести в проект…»** (меню беседы) — тот же `handoff` с `cwd` папки проекта: окно передачи с выбором проекта
  (`ProjectPicker` из `new-chat.tsx`, можно создать новый), агент любой, в том числе тот же. Демон проверяет, что источник —
  беседа, а цель — существующая папка вне `~/chat`. Первое сообщение — `promoteMessage`: история в файле, файлы беседы
  лежат в её папке, перескажи, что относится к проекту, и жди команды.
- Продолжить беседу в терминале: меню чата → «Скопировать команду» (`cd ~/chat/<папка> && claude --resume …`).

## Голосовой ввод

- Кнопка 🎤 в поле ввода (`components/chat/composer.tsx`, логика — `lib/dictation.ts`): `getUserMedia` → `MediaRecorder`
  (Chrome/Android — `audio/webm;codecs=opus`, Safari/iOS — `audio/mp4`), 64 кбит/с, до 5 минут, индикатор громкости.
  Повторное нажатие — распознать, «Отмена» / Esc — выбросить. Текст вставляется в место курсора; при `voiceAutoSend` сразу
  отправляется. На телефоне фокус в поле не ставится — клавиатура не выскакивает.
- `POST /api/transcribe` (`apps/agentd/src/voice.ts`): тело — сырой звук, `Content-Type` — тип записи; проверка Origin как у
  `/api/upload`; ключ читается из `~/secrets/openrouter.env` при каждом запросе (в браузер не попадает) → OpenRouter
  `POST /api/v1/audio/transcriptions` `{model, input_audio: {data: base64, format}, temperature: 0}`, без `language`
  (автоопределение лучше для русского с английскими словами). Запись не сохраняется. Лимит 20 МБ, таймаут 90 с.
- Модели — `VOICE_MODELS` в `packages/protocol`: MAI-Transcribe 2 (по умолчанию), GPT Transcribe, Scribe v2, Whisper Large v3.
  Выбор и `voiceAutoSend` — в `Prefs` (сервер, общие для устройств), окно «Настройки» → «Голосовой ввод».
- **MAI-Transcribe 2 не принимает webm/m4a** (провайдер отвечает 400, проверено 2026-11-13): для моделей с `wav: true`
  браузер декодирует запись и перекодирует в WAV 16 кГц моно (~32 КБ/с, 5 минут ≈ 9,6 МБ). Остальные три принимают webm и m4a.
- Проверка 2026-11-13 (фраза «Сделай коммит и запушь в main, потом проверь deploy на staging и открой pull request…»):
  MAI, GPT Transcribe, Scribe v2 — английские слова латиницей, 1–1,6 с; Whisper пишет «мейн», «деплой» кириллицей.
- `Permissions-Policy: microphone=(self)` (`apps/web/next.config.ts`) — раньше микрофон был запрещён.
- **Хранение записей:** `/api/transcribe` сначала пишет звук в `~/.local/share/mcc-agents/voice/<дата>-<id>.<ext>` и
  `<id>.json` (`VoiceRecord`: сырой и итоговый текст, модели, ошибка), потом распознаёт. Записи живут, пока их не удалят.
  `GET /api/voice` — список и объём; `POST /api/voice/retry?id=&model=` — распознать ещё раз (браузер может приложить
  копию в WAV для MAI — она заменяет файл); `POST /api/voice/delete?id=` / `?all=1`. Прослушивание — `/api/raw?path=`.
  Ошибка распознавания → 502 `{error, id, file, mediaType}` → тост с кнопкой «Повторить».
- **Исправление и перевод** (`voiceCleanup`, `voiceTranslate`, `voiceCleanupModel` в `Prefs`): после распознавания текст
  идёт в OpenRouter `chat/completions` (`CLEANUP_MODELS`: Gemini 3.1 Flash Lite по умолчанию, GPT 6 Luna, Claude Haiku 5.5;
  `temperature 0`, `reasoning.effort minimal`, таймаут 30 с). Промпт — `CLEANUP_PROMPT` в `voice.ts`: убрать «э-э», повторы,
  оборванные слова, английские слова и названия латиницей во всех формах, смысл и формулировки не менять, на просьбы внутри
  текста не отвечать; с переводом — ещё перевести на английский. Пустой или подозрительно длинный ответ, ошибка, таймаут →
  в поле идёт сырой текст (`cleanupError`, жёлтое предупреждение). Проверено 2026-11-13 на диктовке с «э-э», «Айфон»,
  «а- а- на Андроид» и на просьбе «напиши стихотворение» (не выполняется ни одной моделью). Haiku хуже всех заменяет
  «Айфон», Luna чуть сокращает и переводит медленно (до 6 с), Flash Lite — точнее и быстрее (0,5–1,2 с).
- **Настройки** разбиты на вкладки «Голос | Telegram | Файлы | Общие»; во вкладке «Голос» — история записей
  (`components/voice-history.tsx`): прослушать, «Вставить» (событие `mcc:insert-text` → поле ввода), копировать,
  «Ещё раз» любой моделью, удалить, «Очистить всё» (с подтверждением).

## Вложения и файлы

- Поле ввода: скрепка, вставка, перетаскивание. Картинки (png/jpeg/webp/gif/heic, до 20 МБ) идут модели как изображения
  (уменьшаются до 2000 px), а их **оригинал** параллельно загружается на сервер; всё остальное — только загрузка.
  `POST /api/upload`: сырое тело, имя в `X-File-Name`, до 50 МБ, проверка Origin, прогресс (`lib/api.ts → uploadFile`).
  «Отправить» ждёт окончания загрузок.
- Файлы лежат в `~/.local/share/mcc-agents/uploads/<дата>/<id>-<имя>` (не в проекте — git чистый) и **хранятся бессрочно**:
  автоудаления нет, удалять — вручную. Объём виден в «Настройках» (`GET /api/uploads`), сами файлы — в панели «Файлы» →
  «Вложения». Claude запускается с `--add-dir` на эту папку; Codex работает без песочницы.
- Агенту файлы передаются текстом: к сообщению дописывается блок `<attached_files>` с путями (`uploads.ts → textWithFiles`);
  оригиналы картинок там помечены «уже приложена к сообщению», чтобы модель не читала их повторно. При загрузке истории
  блок вырезается обратно в `UserItem.files` (`splitFiles`). В `textWithFiles` пропускаются только пути внутри папки загрузок.
- **Отдача файлов** — `GET|HEAD /api/raw?path=…[&dl=1][&thumb=1][&name=…]` (`raw.ts`), только пути из `allowedPath`
  (`config.ts`): папки проектов (`~/dev`), бесед (`~/chat`), загрузок и `config.readRoots` — артефакты Antigravity
  `~/.gemini/antigravity-cli/brain/` (планы, задачи, walkthrough по папке на разговор) и планы Claude `~/.claude/plans/`.
  Остальной `~/.gemini` закрыт: в `antigravity-cli/` лежит вход CLI (`antigravity-oauth-token`). Все маршруты файлов
  только читают. Пути с `.git`, `.ssh`, `.npmrc`, `.env*` закрыты везде:
  - картинки, PDF, аудио и видео — `inline`; текст любого вида (в том числе `.html`) —
    `text/plain`, чтобы файл из проекта не стал страницей на нашем домене (svg — картинкой, в песочнице); офисные документы, архивы и прочее — `attachment`; `dl=1` — всегда `attachment`;
  - имя в `Content-Disposition` с `filename*=UTF-8''…` (кириллица), у загрузок без префикса `<id>-`;
  - защита: `nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `CSP: sandbox` (кроме PDF — Chrome не рисует PDF в
    песочнице); `Range` (видео на iOS), `ETag`/304; загрузки кешируются навсегда (`immutable`), файлы проекта — `no-cache`;
  - `thumb=1` — JPEG 640 px через Pillow (`python3 -I`), кеш в `~/.local/share/mcc-agents/thumbs/`; для маленьких
    картинок и форматов, которые Pillow не знает, отдаётся оригинал.
- **Просмотрщик** (`components/file-viewer.tsx`, состояние `ui.viewer`): на телефоне на весь экран, на компьютере — большое
  окно. Картинка (нажатие — 100 %), PDF во встроенном просмотрщике браузера (на iPhone — карточка), видео, аудио, текст и код
  с подсветкой; Word/Excel/архивы — карточка. Кнопки: «Скачать» (`dl=1`) и на телефонах «Поделиться» (Web Share API с
  файлом — «Сохранить в Файлы», открыть в Word/Pages; файл скачивается заранее, до 40 МБ, чтобы лист открылся в рамках нажатия).
- Что открывается в просмотрщике: плашки и картинки в сообщениях пользователя; пути к файлам в ответах агента (`код` и
  ссылки — `looksLikeFile` + `resolvePath` от папки чата, `FileBase` в `markdown.tsx`); кнопки 👁/⬇ в заголовках правок и в
  карточках чтения; документы и картинки из панели «Файлы» (текст/код там же в панели, плюс «Скачать»).
- **Ссылки в Markdown**: react-markdown по умолчанию стирает адреса со схемой, кроме http(s)/mailto/irc/xmpp, поэтому
  `[план](file:///…/implementation_plan.md)` и `README.md:12` превращались в пустой `href` (клик открывал саму страницу в
  новой вкладке). Свой `urlTransform` (`linkUrl` в `lib/files.ts`) пропускает `file://` и пути с номером строки, остальное —
  `defaultUrlTransform` (`javascript:` и подобное по-прежнему стираются). Ссылка на файл всегда рисуется как `/api/raw` и
  открывает просмотрщик; `file://` открывается и без расширения; неразобранный `file://` — просто текст.
- **Поиск пути** — `GET /api/locate?path=&cwd=&bare=1&rel=&hints=&touched=` (`locate.ts`). Просмотрщик вызывает его вместо
  `HEAD` перед открытием любого файла, а ссылка — при наведении: в подсказке (`title`) путь, который откроется, или список
  выбора (кеш 30 с). `path` — путь, разобранный от папки чата; `rel` — как его написал агент, если он относительный;
  `touched` — пути, которые трогал этот чат, новые первыми (`touchedPaths`: `file_path`/`path`/`Path`/`TargetFile` из
  инструментов, пути diff, `cd X`/`pushd X`/`git -C X` в командах, `cwd` команд Codex, до 30). Сервер превращает их в корни
  git — ближайший предок с `.git` (папкой или файлом worktree), не выше домашней папки.
  - `path` есть → `ok`. Но если чат работал в worktree и там по тому же `rel` лежит файл с другим содержимым — `choose`
    (worktree сверху): иначе `supa-nest/libs/x.js` из папки чата тихо открывал основную копию вместо той, что правил агент.
  - Иначе `forbidden` (вне `allowedPath`), `eacces`, `not_file` — как есть.
  - Относительный путь, которого нет: `rel` от корней чата (и от их родителя, если `rel` начинается с имени репозитория),
    при пустом результате — от репозиториев папки чата (`cwd/<repo>`, `cwd/worktrees/*/*` и репозиторий самой папки).
    Одно совпадение открывается, несколько — `choose`, недавний репозиторий сверху (до 20). Дальше — поиск по имени в
    последних 5 корнях и в `cwd` (глубина 4, без `node_modules/.git/dist/build/worktrees/.next`, до 20 000 записей) и
    сравнение **по хвосту пути**: подходят только файлы, чей путь кончается на `/<rel>`. Остальные совпадения по имени —
    подсказки в `not_found`.
  - Голое имя (`bare`): сначала `hints` (пути с этим именем из чата, `pathsNamed`) и корни чата, затем поиск по имени в `cwd`;
    одно совпадение открывается, несколько — `choose`.
  - В `not_found` есть `searched` — где искали: папка чата, корни git чата, число репозиториев папки чата. Просмотрщик
    пишет это под путём («Искали: папка чата ~/dev/mcc; репозитории чата mcc-agents, mcc-server…») и добавляет, что
    другие проекты не просматриваются. Так видно, почему не нашёлся файл из соседнего проекта.
  - Других проектов (`~/dev/*`) поиск сознательно не касается: `models/partner.js` в `~/dev/supa` лежит в десятках копий,
    открывалось бы не то. Путь в другой проект должен быть абсолютным. Исключение — путь, который в этом же чате уже был
    написан полностью: он попадает в `hints`, и совпадение по хвосту его открывает.
  `check()` в `fsapi.ts` отвечает 404 на отсутствующий файл и 403 на EACCES или путь вне корней.
- **Ссылкой становится всё, что похоже на путь** (`looksLikeFile`), есть ли файл, проверяется только при открытии и при
  наведении. Заранее проверять каждую ссылку решили не делать (2026-11-26): проверка не тратит лимиты ИИ, но
  ненайденный путь стоит обхода папок (5–22 мс на `~/dev/supa`), а в длинном чате таких сотни, и это нагрузка при каждом
  открытии. Кроме того, файл, созданный после ответа, остался бы текстом до перезагрузки. Узнать по клику несложно, а
  экран «Файл не найден» объясняет, какой путь пробовали и где искали.
- **Пути в ответах**: в системный промпт всех трёх агентов добавлено правило `FILE_PATH_INSTRUCTIONS` (`task-prompt.ts`):
  пути — абсолютные или от папки чата с папкой репозитория, в многорепозиторной папке репозиторий (и worktree) обязателен.
- `.md` рендерится через `Markdown` (переключатель «Просмотр / Исходник»), ссылки внутри считаются от папки файла.
- Тесты разбора ссылок и поиска — `npm test` (`node --test tests/*.test.ts`).
- Проверка: `node scripts/files-test.mjs /run/mcc-agents/local.sock claude|codex <файл>`.

## Непрочитанные

- `lastSeen` хранится в `state.json` — одна отметка на все устройства; ставится, когда чат открыт и виден (`seen`),
  при отправке сообщения и в конце хода, если чат кто-то смотрит.
- Непрочитан: `lastSeen` есть, `updatedAt > lastSeen + 3 c`, чат простаивает. Чаты, ни разу не открытые в оболочке, — нет.
- `updatedAt` двигает `Chat.setStatus` только на реальной активности (ход начался / ждёт подтверждения / закончился /
  ошибка), не на `starting → idle` и `idle → idle` (закрытие простаивающего процесса). При сканировании Claude берётся
  время последней строки `user`/`assistant` в `.jsonl`, а не mtime: при выходе CLI дописывает служебные строки.

## Режим подтверждений по умолчанию

- «Авто» везде, где режим не выбран явно (с 2026-11-16): новые чаты — Claude `auto`, Codex `on-request` («Модель решает»;
  модель и глубина — как в прошлый раз, режим не запоминается); открытый чат без режима в `state.json` (сессии из терминала /
  CloudCLI) — то же (`load()` в обоих адаптерах). Однократная миграция `autoModeMigrated` в `store.ts`: сохранённые
  `default` (Claude) / `untrusted` (Codex) — бывший режим по умолчанию — переведены в «Авто» (на сервере — 3 чата).
- Подпись модели — `matchModel` (`lib/format.ts`): точный id, затем по названию (`claude-opus-5-5` ↔ «Opus 5.5»). Раньше
  было «id содержит», и `claude-opus-5-5` показывался как «Opus 5» (`claude-opus-5`).

## Архив

- Мягкий: пометка `archived` в `state.json` (`meta {archived}`), история CLI, папки бесед и файлы не трогаются; чат по-прежнему
  виден в `claude --resume` / `codex resume`. При архивации чат открепляется; новое сообщение (`send`) снимает пометку.
- Левая панель: архивные чаты не в основном списке, а в свёрнутом разделе «Архив N» внизу (отдельно для «Чат» и «Код»,
  состояние — `localStorage.archiveOpen`; раскрывается сам, если открыт архивный чат). Поиск ищет и по архиву (значок архива).
- Меню строки (`ChatRow`): «⋯» при наведении и правый клик (мышь), долгое нажатие 0,5 с (телефон; клик после него не
  открывает чат) — «Закрепить», «Переименовать», «В архив». У строк архива — кнопка «Вернуть». В меню чата — «В архив» /
  «Вернуть из архива», в открытом архивном чате — плашка с «Вернуть». После действия — тост с «Отменить» (`lib/archive.ts`).

## Форки и откаты разговора

- Только диалог: файлы на диске не трогаются ни форком, ни откатом. Пока агент работает — нельзя (ошибка с сервера).
- `fork {chatId, title, beforeItemId?, rewind?}` → адаптер `fork()` → `created {reqId, chatId}`.
  - **Claude** (`forkSessionFile` в `claude/sessions.ts`): копия `.jsonl` до строки с `"uuid":"<beforeItemId>"` (не включая) под
    новым `sessionId` (подменяется только поле `sessionId`, строки байт в байт) + строка `custom-title` с названием ветки —
    её видит и `claude --resume`. Без процесса CLI и без запроса к модели. Папка (cwd) та же.
  - **Codex**: `thread/fork {threadId, lastTurnId}` — ход перед тем, в котором лежит сообщение (`thread/turns/list`), затем
    `thread/name/set`. Отката до первого сообщения нет (разговора до него ещё нет) — кнопки у первого сообщения скрыты.
- Codex не даёт удалить тред (`thread/delete`), пока на него ссылаются его форки: «forked history still references it» —
  сначала ветки. Важно, если появится настоящее удаление.
- Метаданные (`state.json`): у ветки `forkOf` (значок ветки в списке) или `rewoundFrom`; у исходного чата при откате —
  `hidden` (не в списке, на диске всё есть). `unrewind` — исходный снова виден, ветка-откат скрыта.
- Веб: под своими сообщениями «Копировать / Форк отсюда / Откатиться сюда» (`MessageActions` в `items.tsx`; на телефоне видны
  всегда, с мышью — при наведении), «Форк чата…» в меню чата. Окно форка (`fork-dialog.tsx`) предлагает «<название> — ветка N»,
  название можно сразу переписать. Текст сообщения, с которого ветка/откат, подставляется в поле ввода (`draft:<id>`).
  В откатанном чате — плашка «Вернуть как было», то же — в тосте после отката.
- Проверено 2026-11-16 на Claude и Codex: «запомни 7 / запомни 100 / какие числа?» → в ветке до второго сообщения модель
  знает только 7; откат и «Вернуть как было» возвращают исходный разговор целиком.

## Продолжить в другом агенте

- Меню чата → «Продолжить в другом агенте…» (а под ошибкой о лимитах / квоте — кнопка, `LIMIT_RE` в `items.tsx`). Окно
  (`handoff-dialog.tsx`): другие агенты, модель / глубина / режим (как у нового чата: прошлые модель и глубина, режим «Авто»),
  комментарий. Пока агент работает — нельзя.
- `handoff {reqId, chatId, agent, settings, note}` → `hub.ts`: история исходного чата грузится **с диска** (`ensureLoaded`:
  Claude — `.jsonl`, Codex — `thread/turns/list`, Antigravity — `session/load`) — старый агент не спрашивается, его лимиты не
  тратятся. `handoff.ts` собирает Markdown и кладёт его во вложения (`uploads/<id8>-история-<агент>-<дата>.md`); новый чат —
  тот же `startChat`, что у «Новый чат», **в той же папке** (у бесед — та же `~/chat/…`), с прежним названием; первое
  сообщение: «Продолжаем разговор из … — история в файле, перескажи и жди команды» + комментарий, файл — вложением.
- Что в файле (так удобнее принимающему агенту): сообщения пользователя и ответы агента — дословно (если всего больше ~300 тыс.
  символов, ранние длинные ответы сокращаются до 1500, последние 12 — целиком); команды — строкой с кодом выхода, вывод (хвост,
  ≤ 20 строк / 2000 символов) — только у упавших и у последних 5; правки — файлы с `+N −M`; чтение / поиск / веб — строкой;
  шаги субагентов и мысли — нет; ошибки и предупреждения — цитатой. В конце: список задач агента и git (ветка, последний
  коммит, `status --short`, `diff HEAD --stat`).
- **У беседы** (`isChatDir`) файл другой: только реплики, поиски в интернете и созданные/изменённые файлы, без команд,
  чтения и git. Первое сообщение: «напомни, о чём говорили, и продолжай беседу», без «сверься с git» и «жди команды».
  `cwd` в `handoff` — перенос беседы в проект (см. «Режимы»).
- Связи (`state.json`): у нового `handoffFrom`, у исходного `handoffTo` (последний) → плашки «Продолжение чата из …» /
  «Продолжен в … → Открыть», значок ⇄ в списке.
- Проверено 2026-11-23: Antigravity → Claude, Claude → Antigravity, Claude → Codex (сквозной тест на тестовом демоне), Claude →
  Codex из окна в браузере; каждый агент прочитал файл, сверился с git и ждал команды. Кнопка под ошибкой лимита — не
  проверена на настоящей ошибке.

## Уведомления и подтверждения в Telegram

- **Ход закончился** — по умолчанию ничего не приходит (с 2026-11-18, по просьбе пользователя). Только если в меню чата
  включено «Сообщить в Telegram, когда закончит» (`meta.notifyDone`, колокольчик в шапке) и чат в этот момент никто не смотрит —
  одно сообщение `notify` (бот сервера) «✅ Готово» / «⚠️ Ошибка» со ссылкой; после окончания хода флаг снимается сам.
  Отключить совсем: `AGENTD_NOTIFY=0`.
- **Агент ждёт ответа** (подтверждение, вопрос, план) и в вебе не ответили за `prefs.telegramDelaySec` (по умолчанию 60 с,
  настройка в окне «Настройки») — сообщение с кнопками от **отдельного бота агентов** (`telegram.ts`, `tg-approvals.ts`):
  - команда / правка / прочее: «Разрешить», «Отклонить» и до двух вариантов из `Approval.options` («до конца сессии», «всегда…»);
  - вопрос с одним выбором — кнопка на каждый вариант; несколько вопросов / мультивыбор / свой ответ — только в вебе;
  - план — «Начать» (и «Начать + принимать правки»); замечания — в вебе;
  - всегда кнопка-ссылка «Открыть чат».
- Ответ в одном месте отражается в другом: решение из веба (`hub.handle('decide')`) и из Telegram (`onCallback`) пишется в
  `TgApprovals.record`, а когда запрос исчезает из `chat.state.approvals` (`Chat.patch` → `sink.approvalRemoved`), сообщение
  редактируется: «✅ Разрешено в вебе / в Telegram», «⛔ Отклонено…», «💬 Ответ…» или «⌛ Неактуально» (ход прерван, процесс закрыт).
  Отправленные сообщения хранятся в `state.json` (`tgMessages`); после рестарта демона они помечаются «неактуально».
- Почему отдельный бот: бот сервера `@<бот_сервера>` использует `ops`, который читает нажатия через `getUpdates` и держит
  смещение в недоступной `dev` папке; два читателя одного бота крали бы нажатия друг у друга. Принимаются только нажатия
  из `TELEGRAM_CHAT_ID`. Токен подхватывается без рестарта (проверка раз в минуту).
- Без токена бота агентов — прежнее поведение: сразу `notify` «нужно подтверждение», если чат никто не смотрит.

## Приложение на экране «Домой» (iOS)

- `appleWebApp.statusBarStyle: 'black-translucent'` (`app/layout.tsx`): страница идёт под строку статуса, `env(safe-area-inset-top)` =
  настоящий отступ (62 pt на iPhone 17 Pro), шапки (`.pt-safe`) опускаются под строку статуса. Со стилем `default` отступ был 0, а
  в iOS 26 у верхнего края приложения рисуется размытие Liquid Glass — заголовок шапки попадал под него.
- Высота приложения — `hooks/use-app-viewport.ts` → `--app-h` / `--app-top` / `data-keyboard`. Без клавиатуры в режиме
  веб-приложения берётся `100lvh` (iOS 26 занижает innerHeight/visualViewport/dvh на высоту строки статуса). «Клавиатура
  открыта» = в фокусе поле ввода и visualViewport заметно короче экрана — на innerHeight не опираемся (в разных версиях iOS
  он то сжимается с клавиатурой, то нет). Если iOS сдвигает visualViewport (offsetTop), приложение сдвигается за ним
  (`transform` у `.app-h`). Пересчёт — по событиям visualViewport и по focusin/focusout с повторами (клавиатура выезжает
  с анимацией, у сторонних клавиатур события приходят поздно). Выезжающие панели и подложки диалогов — по `--app-h`.
  При открытой клавиатуре `.pb-safe` не добавляет отступ полоски «Домой».
- Диагностика: «Настройки → Диагностика → Показать размеры экрана» (или `?debug=1`) — плашка с размерами viewport,
  safe area, состоянием клавиатуры и `--app-h` (`components/debug-overlay.tsx`).
- Иконки: `app/icon.tsx`, `app/apple-icon.tsx` (квадрат без скругления — iOS скругляет сам), `app/app-icon/[variant]` —
  192, 512 и `maskable` (с безопасной зоной) для manifest; рисунок — `lib/app-icon.tsx`. Иконки и manifest открыты без входа (nginx).
- Иконки из манифеста для Android имеют светлый фон, близкий к цвету стартового экрана. Параметр версии в URL иконок помогает Chrome обновить сохранённые изображения. Первую анимацию запуска рисует Android.
- **Размытие верха (iOS 26/27, только на реальном устройстве):** система размывает верхний край веб-приложения на экране
  «Домой» (Liquid Glass scroll edge effect, зона ~строка статуса + 36 pt). Выключателя у веба нет; обходы стоят ~36 pt экрана
  (сплошная полоса на всю зону, шапка ниже), пробовали — выглядит хуже. Решение пользователя: оставить вёрстку как есть,
  а на телефоне включить «Универсальный доступ → Дисплей и размер текста → Понижение прозрачности» — размытие пропадает.
- В приложении нет адресной строки — «Обновить» есть в меню чата и в подвале сайдбара.
- После смены иконки/manifest приложение на экране «Домой» нужно удалить и добавить заново: iOS кэширует их при добавлении.

## Готовый промпт → новая задача

Ассистент обозначает готовый промпт fenced-блоком с языком `mcc-task`. Инструкция (`AGENT_INSTRUCTIONS` = она же +

Исходный текст берётся по позициям Markdown AST, без HTML, trim и переформатирования; убираются только внешние
ограждения и отделяющий их перенос строки. Внутренние пустые строки и Markdown сохраняются.

Кнопка сохраняет отдельный локальный черновик `draft:task:<uuid>` и открывает штатный `NewChat` с агентом,
точным `cwd` исходного чата и его режимом. В URL только идентификатор черновика (текст остаётся в браузере).

а отдельную папку новой беседы сервер создаёт при отправке. Черновик можно редактировать и сменить агента.

## Архив, удаление из панели и ручные статусы

ChatMeta хранит archived/deleted/taskStage. StoreData.projects хранит archived/deleted
по точному cwd. decorate добавляет эти поля и projectArchived/projectDeleted в
ChatSummary при каждом сканировании. meta обновляет архив/ручной статус, removeChat
требует актуальное название, projectMeta требует basename cwd и обновляет весь проект.
Удаление проекта ставит tombstone всем текущим чатам, а создание нового чата в том же
cwd восстанавливает проект, сохраняя tombstone старых чатов. Источники CLI и каталоги
не изменяются. Сервер проверяет отсутствие выполняемых ходов и фоновых задач перед
удалением. projects() исключает скрытые/архивные проекты из выбора для новых чатов.

AppSidebar фильтрует deleted/projectDeleted, предлагает общий архив и details-группы
архивных чатов в проектах. ChatActions/ProjectActions используют Radix DropdownMenu и
диалог с точным вводом названия. RenameDialog общий для строки и шапки. taskStage
показывается отдельным ручным индикатором, status продолжает отражать состояние CLI.

Composer открывает миниатюру в Dialog с оригиналом или локальной копией во время

горизонтально прокручиваемой области, ячейки имеют минимальную ширину.

Правки только веб-интерфейса можно публиковать `scripts/deploy-web.sh` из SSH через
sudo. Скрипт собирает Next в новой папке, резервирует текущую .next и перезапускает
mcc-agents-web с проверкой HTTP-готовности. В CSS правило pointer ограничено включёнными
кнопками/пунктами меню, исключена ручка sidebar rail. Индикатор ручного статуса
реализован CSS-точкой 6 px, размеры SVG из SidebarMenuButton на него не влияют.
